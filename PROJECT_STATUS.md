# anihub-cli — стан проєкту

> Станом на 2026-07-26 · версія 0.8.0 · 225 тестів

Неофіційний термінальний клієнт для [anihub.in.ua](https://anihub.in.ua):
пошук, бібліотека з прогресом, відтворення через **mpv**.

## Стек

Rust 2024 (MSRV 1.85), один бінарник, без окремого lib-таргета.

| | |
| :--- | :--- |
| UI | `ratatui` 0.30 + `crossterm` |
| HTTP | `tokio` + `reqwest` |
| Стан | `serde_json` на диску, атомарні записи |
| Плеєр | `mpv` через Unix-сокет IPC |
| Постери | `ratatui-image` — Kitty / iTerm2 / Sixel / halfblocks |

~20 900 рядків у 43 файлах.

## Архітектура

```
api/        client (AniHub + AniList), parser (Ashdi), moonanime (embed),
            franchise (граф релізів), grouper, resource (воркер), models
ui/         app.rs + 15 підмодулів стану · render.rs + 3 підмодулі
playback.rs таймлайн, вікно плейлиста, актор-супервізор
player/     spawn mpv, IPC, парсинг подій
storage/    history.rs — прогрес, бібліотека, міграції, відновлення
```

Плюс наскрізні сервіси в корені: `settings`, `cache`, `poster_cache`,
`discord`, `diagnostics`, `resource_coordinator`, `atomic_file`, `platform`.

**Ключовий принцип:** `api/franchise.rs` не робить I/O. Викликач тягне один
батч AniList і будує детермінований каталог із двох наборів даних.

## Що працює

- Пошук: строгий / розширений, групування франшиз (сезони, фільми, спецвипуски)
- Бібліотека: статуси, фільтри, 5 режимів сортування, пошук у бібліотеці,
  бейджі нового контенту, відлік до наступної серії, експорт у JSON
- Відтворення: mpv із нативним плейлистом (±12 серій), resume з таймкоду,
  автоперехід, поріг автопозначки «переглянуто»
- MoonAnime у mpv — **експеримент, типово вимкнено** (див. нижче)
- Синопсис (`i`), таб статистики, налаштування якості (`--hls-bitrate`)
- Теми: AniHub RGB + ANSI 16/256, керування поверхнею й прозорістю
- Discord Rich Presence з прогрес-баром (opt-in)
- Розкладки EN і ЙЦУКЕН — шорткати працюють на обох
- Опційна діагностика в JSONL (`ANIHUB_LOG`)

## MoonAnime

Сторінка embed не віддає посилання на потік у відкритому вигляді: воно за двома
детермінованими шарами обфускації, **ключі обох лежать у самій сторінці**, тож
JS-рухач не потрібен. Деталі — у docstring `api/moonanime.rs`.

Дві неочевидні вимоги, перевірені на живому CDN:

1. Без заголовка `Accept-Language` сервер віддає **400** — і на сторінці, і на
   мастер-плейлисті, і на кожному варіанті. Тому він мусить доїхати **до mpv**,
   а не лишитися в клієнті.
2. `--no-ytdl` обов'язковий: інакше mpv віддає вже розшифрований манифест
   yt-dlp, той переrозв'язує його до одного варіанта 480p і тихо перебиває
   налаштування якості.

Підписані посилання живуть ~120 хвилин, тому розшифровка робиться перед
відтворенням конкретної серії, не пачкою наперед.

Обфускація навмисна → **це постійний ремонт, а не стабільне API.** Тому фіча
типово вимкнена, а при збої повідомлення веде на фолбек у браузер (`o`).

## Відомий технічний борг

| Що | Де | Чому важливо |
| :--- | :--- | :--- |
| `render_lists` 398 рядків | `ui/render/search.rs:539` | найбільша функція проєкту |
| `render_lists` 324 рядки | `ui/render/library.rs:86` | той самий каркас, друга копія |
| `render_sidebar_details_area` 256 рядків | `ui/render/search.rs` | 29 дубльованих рядків між гілками |
| 30 однакових рядків каркасу постера | `search.rs` ↔ `library.rs` | розрахунок висоти і центрування двічі |
| `ui/render/search.rs` — майже нуль тестів | 936 рядків | усе бере `&AppState`, який у тестах не побудувати |
| `apply_event` 192 рядки, 5% тестів | `resource_coordinator.rs:482` | найризикованіший файл для рефакторингу |

`AppState::new` вимагає `Picker` і робить I/O, тому в тестах він не
конструюється. Звідси конвенція: тестуються підструктури стану й чисті функції,
а не рендер застосунку цілком. Щоб зробити рендер тестованим, треба виносити
малювання у функції від простих даних — як зроблено для попапа сортування,
синопсиса й статистики.

## Перевірка

CI (`.github/workflows/ci.yml`) вимагає: `cargo fmt --check`,
`clippy --all-targets --all-features -D warnings`, `cargo test`, release-білд,
плюс shellcheck і тести інсталятора.

Клавіатурний ввід у TUI **не автоматизується** з CI/агентських середовищ:
`Picker::from_query_stdio()` чіпає termios до `enable_raw_mode()`, і синтетичний
pty на це не відповідає. Перевіряти зміни рендеру треба через `TestBackend`.
