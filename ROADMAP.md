# anihub-cli — roadmap

> Актуально для 0.8.0. Історія релізів → [GitHub Releases](https://github.com/NEO-LAX/anihub-cli/releases),
> зміни по версіях → [CHANGELOG.md](CHANGELOG.md).

Попередня версія цього файлу описувала v0.2.1 і встигла розійтися з кодом на
п'ять мінорних версій. Тут лишилося тільке те, що **справді не зроблено** —
перевірено grep'ом по `src/`.

## Найближче

- [ ] **Прапор `--no-anilist`** — вимкнути запити до AniList для офлайну і
      швидкого старту. CLI зараз має лише `--version`, `--migrate-data`,
      `--help`.
- [ ] **Пріоритет студії озвучки** — завжди вибирати вказану першою.
      Аргументи mpv уже налаштовуються, цього ще немає.
- [ ] **Фільтри пошуку** (`f`) — тип (TV / OVA / фільм), рік, статус.
- [ ] **Підтримка HTTP-проксі** для API та джерел. Наявні згадки `proxy` в коді
      стосуються лише проксі зображень Discord.

## Далі

- [ ] **Справжній вибір роздільності.** Зараз є груба якість через
      `--hls-bitrate` (Авто / макс / мін). Повний варіант вимагає парсингу
      мастер-плейлиста: `#EXT-X-STREAM-INF`, `RESOLUTION`, `BANDWIDTH`, і — що
      легко проґавити — додати вибір до ключа кешу `play_target_cache_key`,
      інакше 10-хвилинний кеш віддасть попередній варіант.
      MoonAnime тут дешевша: її манифест уже містить `RESOLUTION`.
- [ ] **Завантаження серії.** Джерела віддають лише HLS, тому потрібен або
      ffmpeg/yt-dlp (нова залежність → зміни в PKGBUILD, `install.sh`,
      `flake.nix`), або власний завантажувач сегментів. Плюс менеджер
      завантажень і прогрес-UI, якого в проєкті немає взагалі — нуль `Gauge`,
      лише один рядок тексту в статус-барі.
- [ ] **Мультивибір у бібліотеці** — дія над кількома тайтлами одразу. Сторедж
      уже batch-native (`set_anime_statuses`, `set_episodes_watched` — один лок,
      один запис). Складність в іншому: `Space` уже зайнятий, і виділення має
      вижити після зміни фільтра чи сортування.
- [ ] **Скриншоти в сайдбарі** — карусель замість одного постера. Сайдбар уже
      тісний і зникає нижче 110 колонок, тож спершу треба вирішити компонування.

## Не плануємо

- **Синк з AniList / MAL.** Авторизації в проєкті немає жодної: нуль згадок
  oauth / bearer / token, а єдиний «ключ» — це sha256 від константи з датою.
  Потрібні OAuth, безпечне сховище токена (не в plaintext `settings.json`),
  мутації, маппінг статусів і розв'язання конфліктів з локальною історією.
  Для MAL ще гірше — MAL-id ніде немає, лише `anilist_id`.
- **Headless-браузер для MoonAnime.** Був і прибраний. Виявилось не потрібним:
  посилання дістається чистим HTTP, деталі в
  [PROJECT_STATUS.md](PROJECT_STATUS.md).

## Технічний борг

Повний перелік із рядками — у [PROJECT_STATUS.md](PROJECT_STATUS.md). Коротко,
за співвідношенням користь / ризик:

1. Розібрати два `render_lists` (398 і 324 рядки) — спільний каркас панелі й
   таблиця констрейнтів замість матчу. **Спершу тести**: у
   `ui/render/search.rs` їх практично немає.
2. Винести каркас постера в сайдбарі — 30 однакових рядків у двох файлах.
3. `storage/history.rs` → окремий модуль довговічності (локи, бекап,
   відновлення, міграції ≈ 510 рядків). Найкраще протестований файл у проєкті,
   тобто є сітка безпеки.
4. Додати тести до `resource_coordinator.rs` **перед** будь-яким рефакторингом:
   924 рядки коду і ~5% тестів, `apply_event` на 192 рядки мутує спільний стан.

### Відкрите з давнього списку

- `same_franchise` не обробляє транслітерацію — різні написання однієї назви не
  зливаються.
- Глибина BFS по AniList = 2, тож у довгих франшизах (9+ сезонів) частина
  членів може не знайтися.
